Full System Overview — Role-Based Internal Management Platform

This document describes the complete, real-world system design of the project, end to end.
It covers product flow, user journeys, frontend and backend responsibilities, and the mental architecture used while building it.

This is a production-style internal system, not a demo app.

1️⃣ Project Definition

A role-based internal management system where authenticated users (Admins and Staff) manage business data (Employees) through secure APIs.

The system enforces:

Authentication

Role-based access control (RBAC)

Protected routes

Session handling with refresh tokens

Actors

Users: Admin, Staff (they log in)

Employees: Business records being managed

2️⃣ End-to-End Product Flow

This represents the entire lifecycle of the system.

PHASE 0 — Initial Setup

Actor: System / Developer

Backend and frontend are deployed

First admin user is created via a seed script

System becomes operational

PHASE 1 — Authentication Flow

Actor: Admin / Staff

User navigates to /login

Enters email and password

Backend:

Verifies credentials

Generates:

Short-lived access token

Long-lived refresh token

Sends tokens via HTTP-only cookies

Frontend:

Stores authentication state

Redirects user to /dashboard

PHASE 2 — Role-Based Routing

Admin Access

/dashboard
/users
/employees
/logs


Staff Access

/dashboard
/employees


All routes are:

Protected

Role-validated on both frontend and backend

PHASE 3 — Staff Onboarding

Actor: Admin

Admin navigates to Users page

Clicks “Create User”

Creates a staff account

Staff member logs in using provided credentials

This mirrors real internal onboarding workflows.

PHASE 4 — Core Business Operations (CRUD)

Actor: Admin / Staff

Navigate to Employees page

View paginated employee list

Search and filter records

Create new employee

Edit existing employee

Delete employee (Admin only)

This represents the primary operational functionality.

PHASE 5 — Security Handling

Token Expiry

Automatic silent refresh

No forced logout during normal use

Unauthorized Access

403 response from API

Frontend redirect to access-denied page

Rate Limiting

Prevents abuse and spam requests

PHASE 6 — System Auditing

All critical actions are:

Logged

Timestamped

Viewable by Admins

This enables traceability and accountability.
